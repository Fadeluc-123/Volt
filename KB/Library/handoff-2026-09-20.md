## 1. Where we are

Mike is starting a brand-new Roblox project and spent this session evaluating the two buffer-based networking code generators:

- Zap, https://github.com/red-blox/zap, latest v0.6.29 (2026-06-23). Rust compiler, Luau output. MIT.
- Blink, https://github.com/1Axen/blink, latest stable v0.18.9 and pre-release v1.0.0-pre.10 (both 2026-09-19). Luau compiler, Luau output. MIT.

ByteNet is out of scope and stays out of scope.

The research report recommended Zap for a new project because Blink is mid-rewrite. Mike then decided he leans toward Blink's approach, does not like several things in both, and wants to **build our own package**. He was told the runtime is small and the compiler is the expensive part, and that forking Blink is the cheap route. He read Blink's generator source and understands the full pipeline. His current position, which this handoff records as the working decision:

> Build our own package completely from scratch. Use Blink and Zap as source references for what they each do well. Fix every known issue and bug in both. Improve runtime performance. Remove `_G`. Keep the package lightweight and simple.

A fork of Blink remains an explicit alternative. Section 4 says when each is the better call. The next session must make a recommendation between them, not assume.

## 3. Goals for the package, in Mike's words and order

- Increase runtime performance over Blink and Zap.
- Lightweight codebase.
- Simple, easy-to-understand usage, so that a wrapper system can be built on top that replaces Knit.
- Use-case coverage and fixes for what Blink and Zap miss or leave incomplete.
- Known bug fixes for everything listed in section 6.
- Decreased CPU usage and decreased bandwidth usage.
- Buffers, packets, Heartbeat batching.
- Security and validation for every byte the server reads.
- No `_G`. Mike does not use `_G` anywhere in his runtime code.
- An improved, lightweight, simple package: minimal runtime, minimal generated code, and a simple install and distribution story. Confirm this reading with Mike if the design hinges on it.

## 4. From scratch versus fork of Blink

Both are on the table. Recorded tradeoffs:

**From scratch wins when:**
- We want a different IDL surface than Blink's, or a different generated API shape, and the changes touch the parser, the block builder, and the templates all at once.
- We want to design validation, packet caps, rate limiting, and decode-failure policy into the runtime from day one rather than retrofit them.
- We want a smaller generator than Blink 0.18's roughly 80 KB across `Generator/init.luau`, `Prefabs.luau`, `Blocks.luau`, `Typescript.luau`, or than Blink 1.0's much larger HIR/LIR pipeline.
- We want to avoid inheriting Blink's two-track syntax split and its open 1.0 bugs.

**Fork wins when:**
- Time to a working, tested compiler matters more than owning every line. Blink 0.18.9 works today, and its runtime concerns are solved.
- The changes we want are additive: remove the `_G` guard, add packet caps, add bitpacking, fix listed bugs, change casing or output layout.
- We want the Studio plugin and VS Code extension without rebuilding them.

Reference cost: Blink is one author, 91 releases over roughly 2.7 years. Zap's Rust compiler is larger still. A from-scratch generator that reaches feature parity is months, not weeks. A from-scratch generator scoped to what this project actually needs, with a coverage matrix to keep it honest, is the realistic path.

Language for the compiler if from scratch: Luau, run outside Roblox under Lune (Blink 0.18) or Lute (Blink 1.0). The generated output must be plain Luau with zero runtime dependency on the compiler. Mike should be able to patch the compiler without a Rust toolchain.

## 5. Strengths to borrow

### From Zap
- Documentation structure: nine focused pages, per-option version tags, and an in-browser playground that shows generated output live. Copy the structure.
- TypeScript output that works, with `typescript_enum` and tuple-length options. Blink 1.0 accepts the option and emits nothing.
- Bitpacking for booleans (v0.6.24 and v0.6.25). Blink 1.0 still has no bitpacking (issue #105 open).
- Ordered unreliable events, `AlignedCFrame`, `FireSet`.
- A documented tooling deserializer for packet inspectors like PacketProfiler.
- Server-side validation always on; `write_checks` only toggles sender-side checks.
- OR types, recursive types, namespaces (v0.6.21), five call modes including Polling, `manual_event_loop`, `include_profile_labels` for microprofiler labels.
- Stable IDL: v0.6.x declared feature complete September 2024, few breaking changes since.

### From Blink 0.18
- Luau codebase. Approachable, patchable, forkable.
- The `Blocks` builder: one `Allocate(n)` or `Read(n)` per block with constant offsets, and one allocation for a whole array of fixed-size elements before the loop. This is the core of Blink's CPU edge. Reuse the idea.
- Read and write code emitted from the same tree walk, so the two sides cannot disagree on layout.
- Per-player server send buffers with `Save` and `Load`, flushed once per Heartbeat.
- `export` types that generate standalone read and write functions, useful for custom serialization and DataStores.
- Generics, multi-file `import`, scopes, `f16`, per-component `CFrame<i16, f16>` and `vector<u8>` encodings.
- Official Studio plugin, Rokit and pesde install, GitHub binaries.
- A test harness that mocks RemoteEvents through a bridge so generated modules can be unit tested outside Roblox (`test/Shared.luau`, `test/Client.luau`, `test/Server.luau`).

### From Blink 1.0 pre-release
- Compilation profiles: `release` strips write validation, `debug` keeps it.
- Attributes on declarations, literal types, real unions, recursive types, `u24` and `u48`, an `integer` type, `StreamedInstance`, Roblox `Enum` type, named parameters, `from: Both` two-way events, everything under a single `.exports` table.
- No `_G` anywhere in generated output. The duplicate-instance guard was dropped entirely.

## 6. Known bugs and issues to fix in ours

All confirmed this session from GitHub issues and release notes. Numbers are GitHub issue numbers in the named repo.

### Shared by both
- **Oversized-buffer denial of service.** Both trust the incoming buffer length and iterate over it server-side. Zap #219 (March 2026) reports real production crashes; Blink #45 (May 2025) is unanswered. Ours: hard cap on incoming buffer length, per-player fire rate limit, both checked before any decode.
- **No documented decode-failure policy.** Blink #102: a nil non-optional Instance drops the rest of the packet silently. Ours: a defined policy per event, with drop-packet as default and an optional kick hook.
- **Yielding inside a sync callback is undefined behavior** in both. Ours: either detect and error clearly in debug, or make sync listeners impossible to yield from by design.
- **Unreliable payload cap of 1000 bytes** with no fragmentation in either. Ours: reject at compile time when the schema's maximum size exceeds the cap, or document fragmentation as out of scope.
- **`_G` duplicate-instance guard** in Zap 0.6 and Blink 0.18. Ours: none. Unique remote scope per generated module instead.

### Zap 0.6.29
- #216: `Player` memory leak when `Fire` is called after `PlayerRemoving`. Community fix PR #223 closed unmerged 2026-09-12.
- #225: generated modules for large games exceed Roblox bytecode limits because Zap emits one monolithic module per side. A studio maintains a sharding fork. Ours: emit sharded or lazily-required modules above a size threshold.
- #67: no 64-bit integers, open since February 2024. Also no 24, 40, 48, 56-bit widths.
- No two-way events, no server-to-client functions, no documented generics.
- v0.6.27 fixed buffer out-of-bounds with 256 or more concurrent function calls, which shows the invocation ring is a fixed 256 slots.
- Maintenance: one release in 2026, rewrite branch dormant since July 2024, unanswered 2026 issues.

### Blink 0.18.9
- #12: Studio plugin editor freezes between roughly 150 and 800 lines of schema, open since July 2024.
- #81: cannot require the client module from Studio edit mode for Storybook-style UI tooling. Zap v0.6.29 supports this.
- `Single*` call modes silently replace a prior listener instead of erroring.
- 256-slot invocation ring for functions with no timeout; the 257th concurrent call errors.
- Tagged enums are not real unions in the emitted Luau types.
- Register exhaustion with many serdes functions, fixed 0.18.7. NaN bypassing range validation, fixed 0.18.9. Both are classes of bug to test for.
- Docs: eleven short pages, CLI page documents one flag, TypeScript gets one sentence, no replication or validation internals, no migration guide.
- Two-track syntax: 0.18 syntax will not compile on 1.0.

### Blink 1.0.0-pre.10
- #90: numeric ranges parsed but never enforced (pre.7). #91: validation error inside `fire()` leaves partial bytes in the outgoing buffer and corrupts the batch. #92: players present before the server module loads break reliable fires. #93: messages received before `on()` silently dropped while the queue grows forever. #94: `vector(range)` crashes at runtime. #98: shipped `examples/generics.blink` fails to compile. #99: options that compile without warnings but do nothing, including `typescript`, `--watch`, `--profile`, `@stable`, `@bitpack`. #105: `@bitpack` not implemented.
- No documentation site. Syntax is learnable only from `examples/*.blink` and release notes.
- Removed versus 0.18: `f16`, unit `enum`, Promise and Future yield modes, `--watch`, TypeScript output.

## 7. Use-case coverage list

The next session turns this into a matrix. Start from the union of both libraries, then add the cases neither handles.

**Types:** u8, u16, u32, i8, i16, i32, f32, f64; f16 (Blink 0.18 only); u24, u48, int64 or `integer` (Blink 1.0 only, Zap #67 open); booleans with bitpacking (Zap only); strings with length bounds, `string.utf8` and `string.binary` (Zap 0.6.24); buffers with length bounds; vectors with component encodings; CFrame with positional and rotational encodings, `AlignedCFrame` (Zap only); Color3, BrickColor, DateTime, DateTimeMillis; Instance with class constraint, `StreamedInstance` (Blink 1.0); Roblox `Enum` (Blink 1.0); `unknown`; structs with spread or merge; unit enums and tagged enums; real unions and literal types (Blink 1.0, Zap OR types); maps and sets with size bounds; arrays with size bounds; optionals; tuples and type packs; generics (Blink); recursive types.

**Events:** client to server, server to client, two-way (Blink 1.0 `from: Both`); reliable and unreliable; ordered unreliable (Zap); call modes SingleSync, SingleAsync, ManySync, ManyAsync, Polling; `Fire`, `FireAll`, `FireList`, `FireExcept`, `FireSet` (Zap); named multi-parameter data; events fired before a listener exists (queue semantics and cap); disconnect handles.

**Functions:** client to server with return; server to client functions (neither supports; decide); yield modes Coroutine, Future, Promise; tuple returns; invocation IDs, ring size, and timeouts; error propagation to the caller.

**Organization:** namespaces or scopes; multi-file imports; `export` standalone serializers; casing options; remote scope naming; separate types output; TypeScript `.d.ts` output for roblox-ts.

**Runtime and operations:** Heartbeat batching with `manual_event_loop`; per-player server buffers; Instance side-channel; packet size caps and per-player rate limiting; decode-failure policy and kick hook; schema hash handshake so mismatched client and server builds fail loudly; Studio edit-mode require; microprofiler labels; packet inspector deserializer; large-schema output sharding; mock transport for unit tests outside Roblox; hot reload in Studio; middleware or hook points for a framework wrapper (before-send, after-receive, per-event); memory cleanup on `PlayerRemoving`.

**Wrapper surface for a Knit replacement:** the generated API must be small and regular enough that a service and controller layer can register events and functions by name, attach middleware, and expose typed handles. Decide whether that layer lives in the generated output or in a separate runtime module.

Explicitly missing in both today and worth deciding on: delta compression or dirty-flag replication, interest or relevancy filtering per player, snapshot interpolation helpers, unreliable fragmentation above 1000 bytes. These may belong in the wrapper rather than the transport. Say which.

## 8. Architecture notes from reading the source

Blink 0.18 pipeline, verified from `reference/sources/blink-0.18/`:

1. `CLI/init.luau` parses arguments under Lune, calls `Utility/Compile.luau`.
2. `Lexer.luau`: a table of Lua string patterns tried in order; tokens carry type, value, span. Keywords and primitives come from `Settings.luau`, which also holds each primitive's bounds and allowed attributes.
3. `Parser.luau`: recursive descent with one-token lookahead. Options first, then declarations. Events parsed against a fixed field schema (`From`, `Type`, `Call`, `Data`). Named type references are resolved and inlined.
4. `Generator/init.luau` runs once for Server and once for Client. `Prefabs.luau` holds per-primitive read and write emitters. `Blocks.luau` is a structured-code builder where `Allocate` and `Read` accumulate byte counts and emit one cursor bump per block with constant offsets. A single dispatcher recurses over the tree, building the read block and the write block in the same walk.
5. Final assembly concatenates: header, scope guard, template top half, serdes function table, base runtime (`Templates/Base.luau`), Luau types, an edit-mode no-op branch, template bottom half, Heartbeat connect, the `OnServerEvent` or `OnClientEvent` dispatcher (`while cursor < size` plus an `if`/`elseif` chain on the event index byte), and the frozen returns table.

Zap 0.6 output, verified from `reference/sources/zap-0.6.x/`: same shape, emitted from Rust in `zap/src/output/luau/{client,server,mod}.rs` with `base.luau` as the runtime template. `push_remote_scope_validation` in `mod.rs` emits the `_G.__ZAP` guard unconditionally.

Blink 1.0 pipeline, from `reference/sources/blink-1.0-rewrite/`: lexer, parser, AST, HIR with analysis passes (dereferencing, flattening, instantiation, type checking), LIR with builders per Luau library and per type, an optimizer, then codegen templates. Much larger than 0.18. Worth reading `compiler/lir/build/builders/ty/` for how each type is lowered, and `compiler/codegen/templates/append_server.luau` for the current per-player save shape.

Wire format both use: one-byte event index, then fields in schema order at fixed widths; length prefixes for variable-size arrays and strings; one presence byte per optional; one tag byte per tagged enum; Instances in a side array passed as the RemoteEvent's second argument.

## 9. Benchmark plan

### Existing harness to build on
`benchmark/` in the Blink repo. It is not included in this bundle; fetch it fresh from https://github.com/1Axen/blink/tree/main/benchmark. Files: `Benchmarks.md`, `definitions/Definition.{blink,zap}`, `src/client/init.client.luau`, `src/server/init.server.luau`, `src/shared/benches/{Entities,Booleans}.luau`, `src/shared/modes/*.luau`, `build.bat`, `download.luau`, `generate.luau`, `run.luau`. Requires Roblox Studio, rojo, darklua, run-in-roblox. `download.luau` pulls `releases/latest` for both tools, so pin versions by hand.

### Published results to compare against
Run 2025-04-30, Blink v0.17.1 versus Zap v0.6.20 versus ByteNet v0.4.3, Ryzen 9 7900X. Client fires a reliable event 1000 times per `PostSimulation` frame for 10 seconds with the same table each time.

| Scenario | Blink FPS | Zap FPS | ByteNet FPS | Roblox FPS |
|---|---|---|---|---|
| Entities (100 six-u8 structs) | 42 | 39 | 32 | 16 |
| Booleans (1000 `true`) | 97 | 52 | 35 | 21 |

Bandwidth was identical across the three buffer libraries. The Kbps column is compression-dominated because the payload never changes, so it does not measure encoding size.

### What ours must add
- A third mode for our package in `src/shared/modes/`.
- Current versions: Zap v0.6.29, Blink v0.18.9, and Blink v1.0.0-pre.10 with the definition ported to 1.0 syntax and a `release` profile.
- Zap run twice: default `write_checks = true` and `write_checks = false`, because Blink's write validation defaults off.
- Bytes per packet measured with `buffer.len` on the flushed buffer, not `Stats.DataSendKbps`.
- Isolated serialize and deserialize timings with `os.clock` loops, separate from the FPS test.
- Realistic scenarios: strings, CFrames, optionals, nested structs, tagged enums, server broadcast to many players, many small events per frame, unreliable events, and a validation-cost scenario with malformed packets rejected.
- Memory: module bytecode size and steady-state heap.
- Record the Roblox Studio version. The 2025 run did not.
- Randomized payloads per fire in at least one scenario so bandwidth numbers mean something.
