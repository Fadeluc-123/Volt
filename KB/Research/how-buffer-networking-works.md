# How buffer networking works and why it is generated
Up: [[Research]]

**Question:** What do Zap and Blink actually do on the wire, and why do they need a compiler?

**Answer:**
- **The two wins.** Roblox's `buffer` is a raw byte array (`buffer.writeu8`, `buffer.writef32`, `buffer.readu16` at a byte offset). Sending a buffer through a RemoteEvent costs roughly its length; sending a Luau table costs a type tag per value plus every field name as a string, and one network call per fire. The gains are bytes on the wire and CPU, not memory; generated code can make memory worse (Zap #225: generated modules past Roblox bytecode limits).
- **The machine both libraries build.** (1) One outgoing buffer per side plus a cursor; on the server one buffer per player. Every `Fire` appends a one-byte event ID, then the fields in schema order at fixed widths: `u8` 1 byte, `u16` 2, `f32` 4, `boolean` 1, enum a 1-byte index, array a count prefix plus elements, optional a presence byte, tagged enum a tag byte then the variant's fields. (2) Once per frame on Heartbeat, everything written that frame is copied into a right-sized buffer and sent in a single RemoteEvent call; unreliable events skip the batch and go straight out through an UnreliableRemoteEvent, capped at 1000 bytes. (3) The receiver walks the buffer: read the ID byte, branch to that event's reader, read each field at the promised width, build the Luau value, call listeners, loop until the cursor reaches the end. (4) Instances cannot become bytes, so they ride in a side array passed as the RemoteEvent's second argument and the reader pulls them out in order. Zap additionally inlines resolved types, bit-packs booleans eight to a byte, and offers `manual_event_loop`.
- **Is an external compiler needed?** At build time yes, at runtime no. Both compilers run on the developer's machine once per schema change, like Rojo, and emit plain Luau modules with zero runtime dependency on the compiler. Zap being Rust only matters if you want to patch Zap itself.
- **Why generate instead of a runtime library.** A runtime library (ByteNet) builds serializers from a schema table at game start, paying a "what type is this field" lookup and a function call per field on every write. Generated code is straight-line calls with constant sizes, and because the whole schema is known an event ID fits in one byte. The compiler also produces what a runtime library cannot: Luau type annotations and `.d.ts` for autocomplete, receive-side asserts from constraints like `u8(0..8)`, and a single source of truth so client and server cannot disagree on layout.
- **Worked Blink 0.18 example.** Schema:
  ```
  struct PlayerInput { Dir: u8(0..8), Jump: boolean, Look: f32 }
  event Input { From: Client, Type: Reliable, Call: SingleSync, Data: PlayerInput }
  event Damage { From: Server, Type: Reliable, Call: ManyAsync, Data: struct { TargetId: u16, Amount: u16 } }
  ```
  Client: `Net.Input.Fire({ Dir = 3, Jump = true, Look = 1.25 })` on `PostSimulation`; `Net.Damage.On(function(Data) ... end)`. Server: `Net.Input.On(function(Player, Data) ... end)` with `Data.Dir` already checked 0..8; `Net.Damage.FireAll({...})`, plus `Fire(Player, ...)`, `FireList({...}, ...)`, `FireExcept(Player, ...)`. One `Input.Fire` is seven bytes: `00` event ID, `03` Dir, `01` Jump, `00 00 A0 3F` Look as little-endian f32. Three fires in one frame become one 21-byte packet. Reconstructed from Blink's generator (assert text approximated, not produced by running the compiler):
  ```lua
  SerdesFunctions.WriteEVENT_DATA_Input = function(Value)
  	local BLOCK_START = Allocate(7)             -- one cursor bump per block
  	buffer.writeu8(SendBuffer, BLOCK_START + 0, 0)
  	buffer.writeu8(SendBuffer, BLOCK_START + 1, Value.Dir)
  	buffer.writeu8(SendBuffer, BLOCK_START + 2, Value.Jump and 1 or 0)
  	buffer.writef32(SendBuffer, BLOCK_START + 3, Value.Look)
  end

  SerdesFunctions.ReadEVENT_DATA_Input = function()
  	local BLOCK_START = Read(6)
  	local Value = {} :: any
  	Value.Dir = buffer.readu8(RecieveBuffer, BLOCK_START + 0)
  	assert(Value.Dir >= 0 and Value.Dir <= 8, "Dir out of range")
  	Value.Jump = (buffer.readu8(RecieveBuffer, BLOCK_START + 1) == 1)
  	Value.Look = buffer.readf32(RecieveBuffer, BLOCK_START + 2)
  	return Value
  end
  ```
  Around those functions the generated module holds the buffer runtime from `Templates/Base.luau` (64-byte buffer growing 1.5x; `Allocate`, `Read`, `Save`, `Load`), remotes `BLINK_RELIABLE_REMOTE` / `BLINK_UNRELIABLE_REMOTE` created by the server in ReplicatedStorage, `StepReplication` on `RunService.Heartbeat`, an `OnClientEvent` / `OnServerEvent` handler with `while RecieveCursor < Size do` and an `if Index == 0 then ... elseif` chain, and a frozen returns table of `Fire`, `FireAll`, `FireList`, `FireExcept`, `On`, `Iter` per event. `SingleSync` calls the listener inline; with no listener attached, arguments queue up to 256 deep. One `blink` run produces the client module, server module, optional types file and optional `.d.ts` pair.
