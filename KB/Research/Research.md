# Research
Up: [[Core]]

One node per topic. Research is any finding that took effort to obtain and would take effort to obtain again: how a library behaves, what an engine version supports, a benchmark, the answer to a design question, a comparison of options.

**Read at session start:** listed only (this index, with each node's one-line description). Ruled by Mike 2026-09-20 to keep the injected context small. Before searching the web or reading source, scan the list below and open any node whose description matches the question; the answer may already exist. Open every node relevant to a design task before starting it.

## When to add a node

Whenever a session searches the web, reads documentation, or investigates code and arrives at a conclusion that a future session could reuse. Record it in the turn it was found. If a topic already has a node, update that node and add the new source. Keep the "Answer" factual and short; put reasoning in "Confidence".

## Node template

File name: a short kebab-case slug that names the topic, for example `godot-4-navigation-agent-avoidance.md`.

```md
---
type: research
date: YYYY-MM-DD
session: <first 8 chars of session id>
description: <one line: the question this node answers>
sources: []
tags: []
---
# <Topic, one line>
Up: [[Research]]

**Question:** what needed to be known.
**Answer:** the findings, concise and factual.
**Sources:** URLs, document names or file paths, with dates for anything that can change.
**Confidence:** high / medium / low, and why.
**Applies to:** where in Volt this matters.
Related: [[Planning/...]] [[Standards/...]]
```
